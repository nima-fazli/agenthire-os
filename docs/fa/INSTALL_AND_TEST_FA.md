# نصب و آزمایش آپدیت ایجنت‌های AgentHire OS

این راهنما برای پروژهٔ فعلی تو در `D:\Projects\agenthire-os` و PowerShell نوشته شده است. دستورها را یکی‌یکی اجرا کن. اگر نتیجهٔ یک مرحله با «انتظار» آن فرق داشت، همان مرحله را نگه دار و متن خطا را بفرست.

این نسخه به سرویس پولی، API پولی یا ایمیل واقعی نیاز ندارد. برای دریافت وابستگی‌ها و مدل به اینترنت نیاز داریم. مدل واقعی روی سخت‌افزار خودت اجرا می‌شود؛ حالت Replay بدون دانلود مدل هم قابل آزمایش است.

## چه چیزی اضافه شده؟

- فرد عادی می‌تواند بدون ساختن شرکت حساب بسازد و برای فرصت منتشرشده رزومه بفرستد.
- ایجنت بررسی رزومه، ابزار جست‌وجو و خواندن منبع دارد؛ نتیجه را با نقل‌قول و جزئیات اجرای ابزارها نشان می‌دهد.
- سؤال پیشنهادی ایجنت فقط پس از تأیید کارفرما برای متقاضی قابل مشاهده می‌شود.
- پاسخ متقاضی بررسی تازه‌ای می‌سازد. رزومهٔ ارسال‌شدهٔ قبلی تغییر نمی‌کند.
- دستیار متقاضی فقط به اطلاعات عمومی همان درخواست دسترسی دارد.
- صف پایدار، بازیابی اجرای قطع‌شده، لغو اجرا، محدودیت مصرف، اعلان و صندوق ایمیل محلی اضافه شده‌اند.
- نقش‌های Owner، Recruiter و Viewer همان عضویت‌های شرکتی قبلی هستند؛ متقاضی مجبور نیست یکی از این نقش‌ها را بگیرد.

## مرحلهٔ ۱ — آماده‌کردن فایل‌ها

۱. Docker Desktop را باز کن و صبر کن آماده شود. پایگاه دادهٔ پروژهٔ قبلی باید روشن باشد تا نصب‌کننده بتواند از آن پشتیبان بگیرد.

۲. فایل `AgentHire_Agents_Update.zip` را در `D:\Projects` استخراج کن. مسیر فایل نصب باید این باشد:

```text
D:\Projects\AgentHire_Agents_Update\install_agents.py
```

اگر هنگام استخراج دو پوشهٔ هم‌نام داخل هم ساخته شد، پوشهٔ داخلی را طوری جابه‌جا کن که مسیر بالا درست شود. فایل‌ها را دستی روی پروژه کپی نکن.

۳. در PowerShell اجرا کن:

```powershell
Set-Location "D:\Projects\agenthire-os"
uv run --locked --no-sync python "..\AgentHire_Agents_Update\install_agents.py" --project .
```

**انتظار:** خروجی `status: ready` و تعداد فایل‌ها. این دستور فقط بررسی می‌کند و چیزی تغییر نمی‌دهد. `up_to_date` یعنی همین آپدیت قبلاً نصب شده است. اگر `blocked` دیدی، فهرست `conflicts` را بفرست؛ فایل‌های متفاوت را با اجبار جایگزین نکن.

اگر فقط پیام آماده‌نبودن محیط Python گرفتی، در همین مسیر `uv sync --locked --no-install-project` را اجرا کن و دوباره دستور بررسی را بزن.

## مرحلهٔ ۲ — نصب همراه پشتیبان

```powershell
uv run --locked --no-sync python "..\AgentHire_Agents_Update\install_agents.py" --project . --apply
```

**انتظار:** `status: installed` و `database_backup: saved`. مسیر پشتیبان در خروجی نشان داده می‌شود؛ معمولاً زیر `D:\Projects\AgentHire_OS_Agent_Backups` است.

نصب‌کننده پیش از تغییر کد، فایل‌های تغییرکرده و یک `pg_dump` از PostgreSQL را ذخیره می‌کند. اگر گرفتن پشتیبان شکست بخورد، کد را تغییر نمی‌دهد؛ پایگاه دادهٔ قبلی را روشن کن و دوباره امتحان کن. پشتیبان نصب‌کننده شامل کل حجم فایل‌های PDF نیست. تنظیمات خصوصی، تاریخچهٔ Git و فایل‌های ذخیره‌شدهٔ پروژه هدف جایگزینی نیستند.

## مرحلهٔ ۳ — ساخت و اجرای سرویس‌های جدید

```powershell
docker compose -f compose.yaml -f compose.agents.yaml up -d --build --wait --wait-timeout 240
docker compose -f compose.yaml -f compose.agents.yaml ps
```

ساخت اولیه ممکن است چند دقیقه طول بکشد.

**انتظار:** سرویس‌های `api`، `postgres`، `extraction-worker`، `agent-worker` و `mailpit` سالم باشند. سرویس موقت `migrate` باید با کد صفر تمام شود؛ نسخهٔ پایگاه داده به `0018_local_agents` می‌رسد. در این مرحله هنوز Ollama لازم نیست.

این دستورها اطلاعات قبلی را پاک نمی‌کنند. برای رفع خطا هیچ‌وقت دستور حذف volume یا `down -v` نزن.

## مرحلهٔ ۴ — ساخت شرکت و سه متقاضی آزمایشی


**انتظار:** `seeded: True` و شناسهٔ شرکت و شغل. شرکت مستقل **AgentHire Demo Lab**، یک شغل Backend Engineer و سه درخواست آزمایشی ساخته می‌شوند. حساب‌ها:

| متقاضی اول | `alex@agenthire.example.com` |
| متقاضی دوم | `maya@agenthire.example.com` |
| متقاضی سوم | `sam@agenthire.example.com` |

رمز مشترک **فقط برای این حساب‌های ساختگی محلی**:

```text

```

اجرای دوبارهٔ دستور دادهٔ تکراری نمی‌سازد و پاسخ‌ها و تأییدهای قبلی دمو را به حالت اول برنمی‌گرداند. اگر شرکت یا ایمیل هم‌نام متعلق به حساب دیگری باشد، ابزار متوقف می‌شود و آن را بازنویسی نمی‌کند.

اگر سؤال را قبلاً در اجرای قبلی تأیید کرده‌ای، این مرحله از قبل انجام شده است؛ برای مسیر کامل از حساب جدید مرحلهٔ ۱۰ استفاده کن.


## مرحلهٔ ۱۱ — مدل واقعی محلی، اختیاری

پس از موفقیت مراحل Replay، در PowerShell پروژه اجرا کن:

```powershell
docker compose -f compose.yaml -f compose.agents.yaml --profile live-ai up -d --wait ollama
docker compose -f compose.yaml -f compose.agents.yaml exec ollama ollama pull qwen3:4b
```

دانلود مدل حدود ۲٫۵ گیگابایت است. سرویس مدل سقف حافظهٔ ۶ GiB دارد و بقیهٔ برنامه هم حافظه می‌خواهد. روی CPU هر بررسی ممکن است چند دقیقه طول بکشد؛ سرعت روی همهٔ سیستم‌ها یکسان نیست. اگر حافظهٔ سیستم محدود است، می‌توانی همین نسخه را با Replay بررسی کنی.

در Agent Center، **Execution mode** را **Live local AI** کن و برای یک درخواست **Start review** را بزن.

**انتظار:** اجرای جدید با برچسب `live` ساخته شود، تعداد واقعی توکن‌ها غیرصفر باشد و شناسهٔ مدل **Observed model digest** دیده شود. اجرای Replay قبلی به Live تبدیل نمی‌شود. مدل ابزار را انتخاب می‌کند، نتیجه را می‌خواند و ابزار بعدی را انتخاب می‌کند.

اگر `MODEL_NOT_INSTALLED`، خطای اتصال یا timeout دیدی، همان کد را همراه مقدار RAM سیستم بفرست. برنامه در این حالت نباید بی‌صدا نتیجهٔ Replay تحویل بدهد.

## مرحلهٔ ۱۲ — تست خودکار مسیر کامل روی دستگاه تو

پشتهٔ Docker و دادهٔ دمو باید روشن و آماده باشند:

```powershell
uv sync --locked --no-install-project
uv run --locked --no-sync python -m scripts.agents_smoke
```

**انتظار:** خروجی `passed`. این تست یک متقاضی ساختگی تازه می‌سازد و ورود، تأیید ایمیل، ارسال درخواست، بررسی، تأیید، پاسخ، دستیار و جلوگیری از دسترسی به گزارش خصوصی را از مسیر واقعی API و سرویس‌ها امتحان می‌کند.

اگر قبلاً پورت API را عوض کرده‌ای، آدرس تست را مشخص کن؛ مثلاً:

```powershell
uv run --locked --no-sync python -m scripts.agents_smoke --base-url http://localhost:8080
```

همهٔ آدرس‌های مرورگر این راهنما هم باید با پورت واقعی خودت باز شوند.

برای ارزیابی جداگانهٔ مدل واقعی نصب‌شده:

```powershell
uv run --locked --no-sync python -m scripts.evaluate_agents --mode live --kind recruiter --repeat 1
uv run --locked --no-sync python -m scripts.evaluate_agents --mode live --kind applicant --repeat 1
```

گزارش JSON هر اجرا با نام مستقل زیر `reports` ذخیره می‌شود؛ نتیجهٔ شکست هم نگه داشته می‌شود. این مجموعهٔ کوچک رزومه‌های ساختگی برای عیب‌یابی است و تضمین کیفیت عمومی مدل در استخدام نیست.

## مرحلهٔ ۱۳ — چند رفتار مهم هنگام تست

| کاری که امتحان می‌کنی | نتیجهٔ مورد انتظار |
| --- | --- |
| تلاش Viewer برای انتشار شغل یا تأیید | دسترسی نوشتن نداشته باشد |
| دسترسی متقاضی به گزارش خصوصی شرکت | رد شود و دادهٔ خصوصی برنگردد |
| تغییر معیارهای شغل پیش از تأیید نتیجهٔ قدیمی | تأیید قدیمی رد شود و بررسی تازه لازم باشد |
| لغو اجرای در حال کار | نتیجهٔ دیررس نتواند اجرا را دوباره فعال کند |
| راه‌اندازی دوبارهٔ worker وسط اجرا | پس از پایان lease، از آخرین مرحلهٔ ذخیره‌شده ادامه دهد؛ فراخوانی قطع‌شده ممکن است تکرار شود |
| تایپ پاسخ هنگام تازه‌شدن خودکار صفحه | پاسخ ذخیره‌نشده از کارت بدون تغییر پاک نشود |
| خاموش‌بودن مدل | خطای مشخص Live؛ بدون جایگزینی با Replay |

lease پیش‌فرض ۲۴۰ ثانیه است؛ برای آزمایش بازیابی انتظار چندثانیه‌ای کافی نیست. ارسال ایمیل از نوع at-least-once است و در مرز قطع‌شدن پس از پذیرش SMTP امکان ایمیل تکراری وجود دارد؛ ادعای ارسال دقیقاً یک‌بار نداریم.

## مرحلهٔ ۱۴ — اگر خطا دیدی

این دو دستور را اجرا کن:

```powershell
docker compose -f compose.yaml -f compose.agents.yaml ps
docker compose -f compose.yaml -f compose.agents.yaml logs --tail 80 api agent-worker extraction-worker mailpit
```

شمارهٔ مرحله، کاری که انجام دادی، خروجی واقعی و متن خطای مرتبط را بفرست. رمز، توکن، OTP، فایل تنظیمات خصوصی و رزومهٔ واقعی افراد را نفرست. خطا را با پاک‌کردن دیتابیس یا volume حل نکن.

برای استفاده از اسکریپت‌های قدیمی پشتیبان‌گیری/بازیابی پروژه، ابتدا worker جدید را متوقف کن؛ آن اسکریپت‌ها مدیریت سرویس جدید را ندارند:

```powershell
docker compose -f compose.yaml -f compose.agents.yaml stop agent-worker
```

پس از پایان عملیات قدیمی، آن را با `up -d agent-worker` و همان دو فایل Compose دوباره روشن کن.

## محدودهٔ بررسی این بسته

نتیجهٔ دقیق تست‌های این نسخه در `docs/agents-verification.md` و گزارش‌های مدل در `docs/evaluations` ثبت شده است. محیط سازندهٔ بسته Docker Engine در اختیار نداشت؛ بنابراین اجرای کامل Compose/PostgreSQL/Mailpit باید با مرحلهٔ ۱۲ روی دستگاه تو یا CI انجام شود. تست‌های محلی دامنه، استخراج PDF، ابزارها و مدل واقعی جای آزمون قفل‌های PostgreSQL و نصب ویندوز را نمی‌گیرند.
